# Alpha usability audit — September 7, 2026

Issue: [ISSUE-0091](ISSUES/ISSUE-0091-Core-UX-Release-Pass.md), EPIC-004, NOW.

## Method and benchmark

Reviewed every screen family and interaction category in `App.tsx`, the active `src/ui` components, entry points and feature flags. Exercised representative phone flows against the exported web app and the real account API handlers backed by an isolated local PostgreSQL-compatible test database. Two synthetic accounts represented organizer and participant. No production people, invitations, friendships or plans were modified, and no external messages were sent.

The usability target is familiar social-app behavior: stable primary navigation, obvious people and plan destinations, one main action at a time, short labels, visible selection and save feedback, and details revealed when needed. [Meta's description of Facebook navigation and cross-channel event invitations](https://about.fb.com/news/2024/10/facebook-local-tab-messenger-communities-ai/amp/) informed the comparison. These are design judgments, not a claim of measured parity with Facebook or Instagram.

The main walkthrough used a 390 × 844 browser viewport. RSVP layout was additionally checked at 320 × 740. Browser viewports do not emulate a physical phone's keyboard, OS permissions or messaging apps. This is a complete screen-family inventory with representative runtime coverage, not an exhaustive test of every possible data/device combination.

## Changes made

- Going uses green, Maybe yellow and Not going red throughout RSVP controls, member badges and summaries. Selected controls also have a checkmark and accessible selection state; pending responses remain distinct from declines.
- Shared plans retain the Home / Plans / Create / Saved / Profile navigation. The Plans destination opens actual shared plans for signed-in accounts. Whole plan/update cards are tappable.
- Plan and People tabs separate itinerary/RSVP work from membership and invitations. Inviting opens directly above the people list. Stop reordering/removal appears after Edit stop. Action labels fit phone screens.
- New/edit forms use browser date pickers, validate required fields and real calendar dates, and keep the end date at least the new start date. In-app navigation warns before discarding edits; web reload/close also registers an unsaved-change warning. Concurrent-edit recovery shows the current server details before the organizer chooses to retain their edits.
- Invitations share one Email / Text / Share / Copy component. Message preview is optional, copying has feedback, and failure exposes selectable text. iOS SMS links use the platform-specific separator.
- Profile exposes Account and Friends. Friends have a compact Manage action, clear empty/no-match states, and explicit removal confirmation. Search remains available if the list shrinks while a filter is active.
- General account UI no longer leads with provider API usage. Admin metrics remain available to admins. Place-share dialogs hide local Dev users for signed-in accounts.
- Personal saved copies direct signed-in users to the canonical shared plan for RSVPs. They no longer present prototype RSVP controls that would not notify other members. Discovery's Include someone shortcut likewise opens real shared plans instead of the local tester picker.
- Home update cards no longer crowd discovery, private editing or Saved. Saved-page copy explains where personal copies and group plans live. Search-area controls have a minimum 44px height.

## Remaining beta work

1. Physical iPhone and Android walkthrough: software keyboard/date entry, Google re-entry, email/SMS composer, invite receipt, share cancellation, calendar import and background/resume. The prior real-person sign-in reported by the user is useful evidence, but is not a fresh test of these changes.
2. Notifications outside an open app are still a separate feature. Current RSVP visibility uses foreground refresh; this pass does not add push, automatic email delivery or an unread notification inbox.
3. Personal saved copies and canonical shared plans still coexist. Their handoff is now explicit, but a future single-plan editing model would reduce the remaining conceptual split. That requires product/data-model work beyond this visual pass.
4. Hundreds of accounts were not load-tested. Existing invitation/member caps, request limits, per-user access controls and admin metrics are regression-tested. Polling and provider costs still need measurement before a larger beta; reported Places calls are not comprehensive billing totals.
5. Friends are currently identified by Google email. Display names/avatars, searchable member lists, scalable plan list pagination and accessibility testing with assistive technology are follow-up usability work.

## Validation

New regression cases exercise date validation and distinguish explicit declines from unanswered invitations.

- `npm run verify`: passed, 112 tests; zero lint errors and 17 pre-existing warnings.
- `npm run build:web`: passed.
- `npm run export:android` and `npm run export:ios`: passed.
- `npx expo install --check`: dependencies up to date.

Production completion must additionally follow the repository publishing runbook. Physical-device and larger-beta limitations above remain open after successful exports.
